## 产品概述

藏宝阁宠物爬虫系统的两大核心增强: 爬虫稳定性优化和AI估值准确度提升。爬虫方面需要解决长时间运行中的断点续爬、代理池轮换、自适应重试等问题; AI估值方面需要通过特征工程优化(技能权重/资质百分比/交叉特征)和降级逻辑改进来提升估值准确度。

## 核心功能

- **爬虫断点续爬**: 记录已完成的列表页码,任务中断后从断点恢复,避免重复爬取
- **代理池集成**: 支持多代理IP轮换,降低被封禁风险(MyWebDriverPool已有代理配置但被注释)
- **自适应重试策略**: 根据失败类型(网络超时/认证失效/页面异常)采用不同重试策略,指数退避
- **AI估值特征工程增强**: 新增技能价值权重(特殊技能加分)、资质百分比(当前值/满资质)、成长与等级交叉特征
- **Python AI服务降级逻辑优化**: 基于技能类型的精确估值公式替代简单线性公式
- **估值缓存机制**: AI服务不可达时使用本地规则引擎缓存,而非直接返回price*1.0

## 技术栈

- 后端: Java 8 + Spring Boot 2.2.6 + WebMagic 0.7.3 + Selenium 2.33.0
- ORM: MyBatis-Plus 3.3.0
- AI服务: Python FastAPI + scikit-learn RandomForest
- 数据库: MySQL 8.x

## 实现方案

### 一、爬虫稳定性优化

#### 1.1 断点续爬机制

在`CbgSpiderTaskExecutor.executeTask()`中增加列表页断点记录:

- LIST_PAGE任务执行前检查是否已完成(通过URL去重)
- 列表页处理器(`CbgPetListPageProcessor`)解析完每页后标记该页完成状态
- 详情页任务天然支持断点: 每个详情页是独立任务,失败的自动重试即可

#### 1.2 代理池激活与轮换

`MyWebDriverPool.java`(第149-158行)已有代理配置但被注释:

```java
// options.addArguments("--proxy-server=http://"+host+":"++":"+port);
```

需要:

1. 在`CbgAuthConfig`中增加代理配置字段(proxyEnabled/proxyHost/proxyPort)
2. `CbgMhxySeleniuDownloader`构造时读取代理配置并传递给`MyWebDriverPool`
3. 支持多代理列表轮换(每次创建WebDriver时切换代理)

#### 1.3 自适应重试策略

在`CbgSpiderTaskExecutor.executeTask()`的catch块中:

- **网络超时**(SocketTimeoutException): 指数退避重试(1s->2s->4s->8s,最多3次)
- **认证失效**(AuthInvalidException): 不重试,直接标记失败并停止调度器
- **页面异常**(RuntimeException如redirect_to_home): 延迟30秒后重试1次
- 重试耗尽后才调用`failTask()`,并在`CbgSpiderTask`表中记录失败原因用于分析

#### 1.4 WebDriver实例复用

当前问题: 每次`executeTask()`都创建新的`CbgMhxySeleniuDownloader`,内部又创建新的`MyWebDriverPool`
优化: 将`CbgMhxySeleniuDownloader`提升为Spring单例Bean或使用对象池,减少Chrome进程频繁启停开销

### 二、AI估值准确度提升

#### 2.1 Java端特征工程增强 (`MhValuationServiceImpl.valuatePet()`)

新增特征:

| 特征名 | 说明 | 计算方式 |
| --- | --- | --- |
| skillScore | 技能价值评分 | 解析skillList,特殊技能(须弥/力劈/壁垒等)加权计分 |
| qualPercent | 综合资质百分比 | 各资质求和 / (满资质 * 资质数量) |
| growLevelScore | 成长等级评分 | growUp * level (高成长+高等级更值钱) |
| rareSkillCount | 特殊技能数量 | skillList中稀有技能个数 |


#### 2.2 Python AI服务优化 (`ai_service/mh_ai_service.py`)

1. **新增特征字段接收**: ValuationRequest增加skillScore/growLevelScore/qualPercent/rareSkillCount
2. **改进降级公式**:

```python
# 当前(过于简单):
base = attackQualification * 0.5 + growUp * 2000 + skillNum^2 * 100

# 优化后(基于游戏知识):
skill_weight = base_skill_price * (1 + rareSkillCount * 0.3)  # 稀有技能加成30%
qual_bonus = qual_percent * price_base * 0.5  # 高资质加成
grow_bonus = growUp * level * 500  # 成长x等级交叉特征
estimated = skill_weight + qual_bonus + grow_bonus + collect * 3
```

3. **增加特征标准化**: 使用MinMaxScaler对数值型特征归一化

#### 2.3 估值缓存与容错

- AI服务调用成功后,将结果缓存到本地Map(按code+updateTime为key)
- AI服务不可达时,先查缓存;缓存未命中才用本地规则引擎
- 本地规则引擎实现一个纯Java版本的`PetValuationCalculator`作为最终fallback

### 三、数据库变更

- `cbg_spider_task`表: 增加`completedPages`字段(JSON格式,记录已完成的列表页码) - 可选,也可通过查询DETAIL_PAGE子任务状态推断
- `cbg_auth_config`表: 增加`proxy_enabled`/`proxy_list`字段 - 用于代理配置
- `mh_pet_item`表: 增加`skill_score`/`rare_skill_count`/`qual_percent`字段 - 用于存储计算后的衍生特征

## 关键架构设计

```
改进后的数据流:
用户请求 -> 创建任务(含代理配置) 
         -> 调度器轮询(PENDING任务) 
         -> 执行器获取任务 + 选择代理 
         -> 下载器(Selenium+Cookie+代理) 
         -> 处理器(列表页/详情页解析) 
         -> 数据存储(MhPetItem + 衍生特征计算) 
         -> AI估值(增强特征 -> Python服务 或 本地Fallback) 
         -> 结果入库(估值+评分+标签)
```

## 实现注意事项

1. **向后兼容**: 新增数据库字段要有默认值,不影响现有数据
2. **代理配置可选**: proxy_enabled默认false,不配置时代理行为与现在一致
3. **AI服务接口向后兼容**: Java端发送的新特征Python端可选接收,旧代码不受影响
4. **日志完善**: 关键节点(代理切换/重试/缓存命中)都要打日志便于排查
